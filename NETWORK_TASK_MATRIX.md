# Матрица стабилизации заданий

Дата: 2026-10-04. Начальные схемы создаёт `network/taskState.js`; тот же код используется браузером, сервером и Reset. Строка главы охватывает перечисленные последовательные практические шаги; проверка каждого контракта отдельно находится в `tests/task-preconditions.cjs`.

## Начальное состояние и переходы

| Глава | Начальное состояние | Шаги и проверяемый результат |
| --- | --- | --- |
| 1, первая сеть | Два ПК, SW-01, кабелей нет | PC-01 → Switch, PC-02 → Switch; реальные Link UP; серверная проверка, карточка пакета и итоговый вопрос |
| 2, Ethernet | PC-01 уже подключён; PC-02 свободен | PC-02 → SW-01; физический путь и Link UP |
| 3, Switch, TRAINING | Три свободных ПК; восемь свободных портов Switch | PC-01 → Port 1; PC-02 → Port 2; PC-03 → Port 3; подтверждение таблицы портов; передача |
| 4, пакет | Два ПК подключены к Switch | Передача по существующему пути, серверная проверка |
| 5, IPv4 | Кабели готовы; IPv4 PC-02 пуст | Четыре октета; сохранение; уникальный допустимый IPv4 в нужной сети |
| 6, /24 | Кабели готовы; PC-02 в другой подсети | Изменение IPv4; сохранение; совпадение сети с PC-01 |
| 7, Router | Две LAN; Router отсутствует | Добавить Router; SW-A → Router; Router → SW-B; доступ между сетями |
| 8, Gateway | Router и кабели готовы; обратный шлюз PC-02 пуст | Заполнить шлюз; сохранить; проверка обратного пути |
| 9, диагностика | Готовая LAN; журнал команд пуст | Успешные ping loopback и соседнего ПК; итоговая проверка |
| 10, DHCP | Сервер готов; новый Laptop без кабеля и адреса | Кабель Laptop → Switch; аренда DHCP; полученные параметры |
| 11, DNS | Сервер и кабели готовы; DNS PC-01 пуст | Проверка IP; настройка DNS; nslookup; ping по имени |
| 12, файлы | Черновик пуст; сеть включена | Сохранить C: и Z:; отключить сеть; объяснить недоступность Z: |
| 13, роли | Пять ответов не выбраны | Файловая служба, DNS, DHCP, Web, БД; проверка каждого назначения |
| 14, RAID | Черновик опытов пуст | Наблюдения RAID 0/1/5; выбор резервной копии для защиты от удаления |
| 15, смена | Три назначенные заявки; черновик проверок пуст | Для каждой: две проверки, причина, исправление, повторная проверка жалобы |

У сетевых действий перед показом инструкции проверяются структура, привязка главы, существование устройств, свободные порты обоих концов и включённость портов. Если предусловие не выполнено, маркер и инструкция указывают восстановление. Переход между микрошагами определяется фактическим результатом, а не фактом нажатия кнопки. Для сцен используются существующие проверки ответов и черновиков; physical port conditions к ним неприменимы.

## Ошибки, повтор, F5 и восстановление

Обозначения: **P** — эксперимент разрешён, успех только после проверки; **T** — действие вне текущей цели отклоняется. **Ports** — занятый endpoint не изменяет схему, ошибка называет устройство и соединение; в PRACTICE доступно удаление лишнего кабеля. **F5** — сохраняется актуальная схема/черновик и вычисляется актуальный шаг. **Reset** — текущая схема/черновик сбрасываются, поколение задания увеличивается; XP, завершённые главы и результаты сохраняются. **Restore** — совместимый save мигрирует, несовместимый восстанавливается до начального состояния текущего задания. Старая запись другого поколения не перезаписывает Reset.

В направляемых демонстрациях 2, 5 и 7 действует T. Продолжение разрешено после реального кабеля, заполнения адреса или двух подключений Router соответственно. F5 сохраняет промежуточный выбор и введённые октеты.

## Доказательства и пределы проверки

- `network-state`: детерминированные схемы 1–11 и демонстрации, версия, привязка задания, восстановление выбора инструмента.
- `training-mode`: последовательность устройств и портов, запрет ранних действий, проверка реального Link.
- `task-preconditions`: контракты практики 1–15; выполнимость физических инструкций, занятый/отсутствующий/выключенный источник.
- `task-recovery`: старый повреждённый save, Reset, устаревшие записи и проверки, повторное открытие SQLite после остановки собственного тестового сервера.
- `topology-invariants`: атомарный connect, удаление обоих endpoints, повторные операции, каскад удаления, 500 последовательных случайных операций и девять моделей итоговых неисправностей.
- `network-lab-e2e`: глава 3 со старым PC-01 ↔ PC-03, реальные нажатия, доступность Ports 1–3, совпадение UI с моделью, F5, Reset и завершение.
- `playthrough` + `novice-flow` + `lab-stress`: один зарегистрированный студент проходит 0–15 клавишами, E и UI; для практик 1–8 выполняет ошибочное действие, правильное действие, повтор, Reset и F5; для 9–15 — терминал, DHCP/DNS, файлы/роли/RAID и диагностику по видимым наблюдениям.
- `curriculum`: API и браузерное прохождение 2–15. `instruction-ui`: мобильные микрошаги, терминал, файлы, восстановление/F5 9–15.

Матрица задаёт ожидаемое поведение, а не утверждает отдельное браузерное прохождение каждой комбинации во всех главах. В каждой практике 1–8 браузер проверяет правильное действие, ошибочное устройство, повтор, Reset и F5; занятые порты дополнительно покрыты общими тестами модели. Для 9–15 покрытие распределено между браузерными и модельными/серверными тестами. Апробация с реальными студентами не проводилась.
