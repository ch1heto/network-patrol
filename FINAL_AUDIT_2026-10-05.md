# Финальный UX + CONTENT + BUG AUDIT «Сетевого патруля»

Дата: 5 октября 2026. Главы 0–15 сохранены; новые главы, здания и сетевые технологии не добавлены.

## 1. Реальные найденные баги

- Нейтральный interaction-hint показывался одновременно с primary quest marker у одной цели.
- CSS добавлял ◆, золотую рамку имени и дополнительные акценты. Нейтральный ○ тоже имел золотую подложку.
- ! пересекался с подписью NPC; на мобильном экране HUD закрывал маркер и голову персонажа. Раскрытое меню могло оказаться под панелью задания.
- После серверного ответа HUD обновлялся отдельно от контракта/маркера; синхронизация зависела от следующего кадра. Обновление объединено в обработчике ответа.
- Закрытие терминала оставляло контекст terminal и маркер в скрытом окне. Теперь закрытие возвращает мировой контекст и актуальную цель.
- Файловая сцена после возврата сообщала «сеть включена», даже если сохранённый сценарий был отключён.
- Терминал терял видимый журнал успешных команд при повторном открытии. Итоговые заявки показывали внутренние ключи проверок вместо наблюдений.
- После исправления ошибочной серверной роли и F5 оставался failedTask прежней ошибки. Он очищается при изменении сохранённого ответа.
- Неподтверждённый flush из таймера/visibilitychange мог дать unhandled rejection. Ошибка обрабатывается существующим каналом сохранения; повторные клики кнопки во время её async-действия блокируются.
- Во время анимации проверки стенд уже предлагал кнопку итогов, которой ещё не было. Теперь текущая инструкция просит дождаться результата; следующий доступный контроль становится целью после анимации.
- Неудачное исправление итоговой заявки при возврате теряло результат и могло вести к повтору прежнего решения. Сохраняется последняя проверка, а цель возвращается к пересмотру гипотезы.
- Повтор одной и той же главы мог повторно использовать поколение состояния. Введён возрастающий номер повторов; устаревшие сохранения отвергаются, локальный черновик очищается при начале/окончании повтора.
- Browser tests зависели от одного пути Chrome. Backend-тест удалял фиксированное имя SQLite; занятая БД другой проверки вызывала EBUSY.

## 2. Какие маркеры дублировались и почему

Основной ! рисовался через .quest-target::after. engine/npcs.js независимо показывал #interaction-hint у nearest, не сравнивая его id с текущей целью. CSS .entity-label::before добавлял ◆, а оформление подписи повторяло золотой акцент.

Теперь quest marker имеет приоритет: nearest.id === currentTask.targetId скрывает ○. paintMarker снимает прежнюю .quest-target до назначения новой. В открытом overlay мировые знаки скрыты. Старый альтернативный псевдомаркер task-target больше не рисует !. Имя спокойное; основной ! расположен выше подписи. Мобильная камера резервирует место под HUD и управление.

Автоматические проверки: VISIBLE_PRIMARY_QUEST_MARKERS <= 1; у ближайшей основной цели neutral marker = 0; обычный предмет получает один ○; смена NPC → дверь → устройство → порт снимает старый знак; overlay скрывает мировой мусор; маркер находится выше имени и ниже мобильного HUD. Проверен доступный Port 1 и сохранённый pending cable source после F5.

## 4. Какие формулировки изменены

DHCP может выдавать IP, маску и дополнительные параметры, например gateway и DNS, согласно конфигурации. В учебной модели выдаются все четыре; показывается Discover → Offer → Request → ACK, без настоящего обмена операционной системы. Подготовленные поля первой лаборатории по-прежнему отделены от DHCP.

DNS в учебных материалах и стенде использует college.ru. Проверка по IP предшествует nslookup/ping по имени; она может работать при неисправном DNS.

IPv4: четыре октета 0–255 описывают допустимую запись, но ещё не подходящий адрес устройства. /24 объясняется через три октета сети и последний октет узла, с явным упоминанием других масок. Шлюз не требуется для прямой связи двух устройств одной подсети. Loopback проверяет локальный сетевой стек, кабель не участвует.

Проверены и сохранены различия TCP-сегмент / IP-пакет / Ethernet-кадр, Switch внутри LAN / Router между сетями, RAID / отдельная резервная копия. Новые расчёты parity и бинарного AND не добавлены.

## 10. Известные ограничения

Апробация с реальными студентами СПО не проводилась. Браузерные проверки и визуальный просмотр подтверждают механическую проходимость и показ инструкций, но не доказывают понимание всех текстов живым новичком.

Для глав 0–1 повторяется контрольный вопрос; полный повтор самостоятельной практики реализован для 2–15. Пересборка первой сети доступна в песочнице после освоения темы DNS.

Игра остаётся учебной моделью: нет реального обмена ОС, DHCP/DNS-запросов во внешнюю сеть, ARP/MAC-learning и сложной маршрутизации. Это границы существующего курса, не новые дефекты.

При уже работающем сервере обновления server/app.cjs требуют его перезапуска. Проверки запускали собственные временные серверы; чужой запущенный сервер и production-БД не изменялись.
