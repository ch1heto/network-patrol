# Сетевой патруль

Учебный веб-квест для начинающих студентов. Игровой движок на HTML/CSS/JavaScript, сервер на Node.js, SQLite через встроенный node:sqlite. Реализован последовательный маршрут глав 0–15: от знакомства с сетью до самостоятельной смены.

## Запуск

Нужны Node.js 22.13 или новее и npm. Браузерные тесты используют Playwright Chromium или автоматически найденный Chrome/Edge. Путь можно задать через BROWSER_EXECUTABLE (CHROME_PATH сохраняется как совместимый вариант).

```powershell
npm ci
npm start
```

Откройте http://127.0.0.1:8000/. SQLite создаётся автоматически в storage/patrol.sqlite. Файл БД, аккаунты и сессии не раздаются статическим сервером. Статический python http.server и открытие index.html через file:// больше не поддерживают учебный маршрут – необходим сервер с аккаунтами. Предыдущий localStorage-прогресс не импортируется в аккаунты.

## Учётная запись преподавателя

Публичной регистрации преподавателей нет. Администратор создаёт аккаунт локальной командой. Пароль хранится только как scrypt-хеш с отдельной случайной солью.

```powershell
$teacherPassword = Read-Host 'Пароль преподавателя от 10 символов' -AsSecureString
$env:PATROL_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $teacherPassword).Password
npm run admin:teacher -- prepod 'Преподаватель колледжа'
Remove-Item Env:PATROL_ADMIN_PASSWORD
```

Повторный запуск admin:teacher обновляет имя и пароль существующего преподавателя, сохраняет его ID и группы и закрывает старые сессии. На стартовой странице нажмите «Я преподаватель» и войдите с созданными данными. Создайте группу, задайте курс и число мест.

## Development teacher

Для локальной разработки можно включить создание тестового преподавателя при старте. В production bootstrap полностью отключён, даже если флаг установлен.

```powershell
$env:PATROL_DEV_TEACHER = '1'
npm start
```

Если teacher ещё отсутствует, будут созданы логин teacher, демонстрационный пароль из server/teachers.cjs и имя «Тестовый преподаватель». PATROL_DEV_TEACHER_LOGIN, PATROL_DEV_TEACHER_PASSWORD и PATROL_DEV_TEACHER_NAME заменяют эти значения. Существующий пароль bootstrap не меняет. Для его обновления используйте admin:teacher. Без PATROL_DEV_TEACHER=1 автоматического создания нет.

При запуске выводятся Development teacher ready и Login – teacher. Пароль в консоль не выводится. Для рабочего развёртывания задайте NODE_ENV=production и создавайте преподавателей admin-командой с собственными паролями.

Все формы ввода пароля имеют кнопку глаза с клавиатурным управлением и aria-pressed. Enter в поле отправляет форму; на кнопке глаза переключает видимость без отправки. Ошибка входа остаётся общей для неизвестного логина и неправильного пароля.

## QR с телефона и локальная сеть

QR должен содержать адрес, доступный студентам. 127.0.0.1 на телефоне обозначает сам телефон. Для демонстрации в сети колледжа задайте адрес компьютера-сервера и разрешите входящие подключения в настройках сети.

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '8000'
$env:PATROL_PUBLIC_URL = 'http://192.168.1.10:8000'
npm start
```

Замените пример IP фактическим адресом сервера. Для внешнего размещения используйте HTTPS reverse proxy и PATROL_PUBLIC_URL с https. HOST по умолчанию равен 127.0.0.1, PORT – 8000. PATROL_DB_PATH задаёт другой файл SQLite. Server и admin используют одну функцию getDatabasePath из server/database.cjs. Относительный путь разрешается от корня проекта, независимо от каталога запуска. PATROL_DB поддерживается как прежнее имя переменной; PATROL_DB_PATH имеет приоритет. Оба процесса печатают фактический путь к БД. PATROL_PUBLIC_URL содержит только origin без пути.

Приглашение содержит 32 случайных байта, записанных как 43 символа base64url. В URL передаётся только token. Ссылка и QR создаются сервером; QR формируется локально библиотекой qrcode без внешнего сервиса. Сервер определяет группу, курс, преподавателя и лимит. Студент вводит ФИО и пароль, получает логин вида g2-01. Выбор группы и курса отсутствует. Закрытый invite и заполненная группа отклоняют регистрацию. Удаление ошибочной регистрации деактивирует студента, закрывает его сессии и освобождает место; история результатов сохраняется.

## Полный маршрут

1. Преподаватель входит, создаёт группу и передаёт ссылку или QR.
2. Студент регистрируется по приглашению, записывает свой логин и входит.
3. В IT-кабинете подходит к Алексею. Получает аналогию города, определение сети и схему, отвечает на вопрос с двумя правильными вариантами.
4. Проходит через физическую дверь в коридор, затем в лабораторию 216. Появляется возле соответствующей двери.
5. Сергей, техник лаборатории, объясняет коммутатор, показывает схему. Студент проходит проверку перед практикой.
6. На стенде соединяет PC-01 → SW-01 и PC-02 → SW-01 двумя Ethernet-кабелями. Нажимает «Проверить сеть». Сервер проверяет топологию, порты, Link и подготовленные IP/маски. При ошибке объясняет причину; при успехе движется маркер данных.
7. После практики студент открывает объяснение пакета и отвечает на итоговый true/false-вопрос. Только после всех обязательных шагов глава завершается и выдаются 100 XP.
8. После главы 1 новая цель ведёт к Сергею на главу 2. Дальше идут Ethernet/Link, порты, пакет, IPv4, маска, Router, gateway, терминал, DHCP, DNS, ресурсы, серверные роли, RAID и самостоятельная смена.
9. Результат и попытки сохраняются в SQLite. Преподаватель открывает группу, видит таблицу и подробности по студенту. Кнопка обновления получает новые результаты.

WASD/стрелки – движение, E – действие поблизости, Escape – закрыть окно. Desktop не имеет постоянных кнопок движения. Touch D-pad включается для сенсорного устройства. Подсказка управления показывается один раз; её состояние – единственная настройка localStorage. Справочник и произвольные эксперименты стенда сохранены.

## Архитектура

- data/ – реестры локаций, NPC, глав, диалогов, учебных карточек и заданий. data/curriculum.js содержит карточки и задания глав 2–15; requiredFlags задаёт завершение глав.
- engine/ – прежние движение/камера/collision/сцены, диалоги, HUD и события. engine/save.js отправляет запросы последовательно; учебные результаты принимает только от сервера. В браузере нет авторитетной копии XP или результата.
- network/ – устройства, порты, кабели, маршруты и диагностика. network/validation.js проверяет структуру модели до симуляции. engine/tasks.js – центральный Validation Engine с quiz, matching, classify, connectDevices, configureDevice, terminalTask, troubleshooting, sequence.
- server/content.cjs – загружает те же данные и чистые валидаторы в изолированный Node-контекст. Сервер не доверяет переданному клиентом correct, XP, group/course или completedChapters.
- server/database.cjs – схема и подключение БД. SQL доступа и транзакции находятся в server/app.cjs; перенос на PostgreSQL потребует замены драйвера, SQL особенностей и транзакционного адаптера, игровой движок менять не требуется.
- server/auth.cjs – scrypt и случайные сессии. Cookie HttpOnly/SameSite=Lax, Secure при HTTPS. Мутации принимают JSON, проверяют Origin; вход и регистрация ограничивают частоту запросов.
- portal.* – вход, регистрация по invite, группы, QR, статистика и подробности.

Таблицы – teachers, groups, group_invites, students, chapters, student_progress, chapter_results, quiz_attempts, practice_attempts, sessions. Лимит мест проверяется в BEGIN IMMEDIATE, поэтому два параллельных запроса не занимают последнее место одновременно. Результат главы имеет уникальную пару student_id/chapter_id. Награда и результат записываются одной транзакцией.

Прогресс учитывает 15 учебных глав: первая включает шесть вводных шагов, остальные – последовательные этапы. После главы 1 общий прогресс равен 7%, после самостоятельной смены – 100%. Средний балл рассчитывается по завершённым учебным главам; до первого результата показывается доля принятых ответов. Балл завершённой главы фиксируется при первом завершении. Практические попытки, подсказки, последний вход/активность, текущая глава и топология хранятся на сервере. Незавершённую схему сохраняет короткая задержка после изменения; подтверждённые проверки записываются сразу. Потеря соединения отображается в обратной связи, локальная награда не выдаётся.

## Проверки

```powershell
npm test
```

Если Playwright Chromium и Chrome/Edge ещё не установлены, выполните `npx playwright install chromium` перед тестами. В PowerShell при блокировке npm.ps1 используйте `npm.cmd`.

22 набора запускают собственные временные серверы и тестовые аккаунты; production-БД не затрагивается. Backend использует уникальные файлы test-backend-<PID>-<timestamp>.sqlite, чтобы не удалять занятую БД другой проверки.

- sanity – синтаксис всех JS/CJS, ссылки на assets, NPC, двери/entry points и обязательный контент.
- task-contracts – обязательные поля каждого шага, реальные объекты и переходы, запрет неполных будущих шагов, последовательные цели и навигация.
- network – IPv4/маски, конфликт, порты/Link, топология, Router/gateway/DNS, quiz и collision.
- backend – права, токены, ограничения мест, закрытие приглашения, удаление регистрации, этапы главы, серверная проверка ответов/практики, XP один раз и восстановление SQLite после перезапуска.
- authentication – создание/обновление через npm admin:teacher, единый путь БД, вход и перезапуск, dev bootstrap/production guard, глаз на desktop/mobile и клавиатура.
- movement – 30/60/120 Hz, диагональ, idle/mirror/scale, collision, resize, недоступный localStorage и запрет игры без аккаунта.
- lab-ui – добавление/drag/настройка/удаление устройств и кабелей, отключение портов, touch, mobile containment, reduced motion.
- world – осмотр каждого значимого предмета, один маркер, постоянные таблички, уникальные NPC, серверная после главы 1, дополнительные занятия, desktop/mobile.
- polish – видимость NPC, отсутствие дублей при повторном render, контекстные подписи, boundary-сцены и mobile HUD.
- curriculum – главы 2–15 через API и полный браузерный маршрут, порядок шагов, объяснения, добровольные подсказки, Network Lab, терминал, DHCP/DNS, ресурсы/RAID, заявки, XP один раз и новая цель без reload.
- instruction-ui – мобильные инструкции без потери ввода, перенос маркера, выбор порта, сохранение микрошагов и повтор tutorial через ?.
- playthrough – преподаватель → группа → декодированный QR → студент → вход → первая глава → серверное сохранение → результаты преподавателя. Тот же новый студент затем проходит главы 2–15 через UI с маршрутами, инструкциями и выбором портов. Проверяет desktop/mobile, изображения и browser console.

Playwright сначала ищет свой Chromium, затем доступный Chrome/Edge. При необходимости задайте BROWSER_EXECUTABLE и PLAYWRIGHT_MODULE. Отсутствие браузера завершает тест ошибкой; skip не используется. Снимки .prototype-checks/slice-*.png и polish-*.png помогают визуальной проверке.

## Ограничения и следующий этап

Завершены главы 0–15. Преподавательская открывается к главе 12; серверная доступна после главы 1 для осмотра, полная тема – главы 13–14. NPC статичные WebP/PNG с idle-анимацией, исходные атласы героя сохранены. Сетевой стенд – учебная модель, без реального сетевого стека, ARP/MAC-learning, Wi-Fi-радиоканала, VLAN/IPv6 или реального shell. Проверяется маршрут через один Router. Нет сброса пароля, импорта старого браузерного прогресса и полноценной admin-панели. Это локальная конкурсная версия; внешнее размещение и PostgreSQL не выполнены.

Следующий этап – методическая апробация курса со студентами и расширение банка заявок. DHCP, DNS, терминал, файловые операции и RAID работают только с учебными моделями; они не меняют сеть и диски компьютера.

## Интерактивный учебный мир

Значимые предметы осматриваются через E или кнопку действия на телефоне: часы, инструменты, стойки, компьютеры, маршрутизаторы, доски, кабели, розетки, полки, мебель, UPS и накопители. Одна подсказка и один маркер «!» относятся к ближайшему действию; фоновые окна и освещение маркеров не имеют. Постоянные таблички дверей показывают номер, название и состояние доступа.

Алексей остаётся наставником в 214. Сергей – техник лаборатории 216. Ирина Викторовна в классе 218 предлагает сопоставить IP/маску/шлюз/DNS, выбрать адрес своей подсети и повторить порядок диагностики. Дмитрий в серверной 222 объясняет аппаратные компоненты, службы, HDD/SSD и RAID; у него отдельный прозрачный PNG. Серверная открывается после завершения главы 1, включая ранее завершённые аккаунты. Дополнительные упражнения не дают повторной награды за главу и не расширяют обязательную цепочку.

Шрифт – system-ui, Segoe UI и Arial fallback, без внешней загрузки. Карточки осмотра находятся в data/worldObjects.js, их интерфейс – ui/worldCards.js, визуальные уточнения – ui/world.css. Справочник дополнен понятиями «Сервер» и «Хранение и RAID». Промпт нового ассета сохранён в assets/npcs/administrator-irina.prompt.txt.

После обновления файлов перезапустите npm start, чтобы сервер загрузил новые задания и правила доступа; затем обновите страницу игры.

## Последовательное обучение

Каждая глава 2–15 содержит сюжет, короткие карточки (одна идея на экран), аналогию, определение и схему. После демонстрации идёт тренировочный вопрос с отдельной причиной для каждого варианта, затем самостоятельная практика. Пока объяснение и тренировка не завершены, практика и новые поля не открываются. Глава 5 использует четыре поля октетов и подготовленную маску; шлюз появляется после главы 8, DNS – после объяснения службы. Главы 0–1 сохраняют прежний маршрут, дополненный понятием host.

HUD показывает текущую главу, шаг и конкретное действие. Золотой маркер указывает нужную дверь, NPC или рабочую станцию. «Что делать?» открывает инструкцию без готового ответа; практические подсказки запрашиваются отдельно, последовательно на трёх уровнях. Подсказки не выдаются автоматически. В главах 2–15 каждая ошибка уменьшает результат на 5 баллов, каждый уровень подсказки – на 10; награда главы выдаётся один раз. Главы 2–14 дают 120 XP, смена – 200 XP.

Сервер проверяет номер главы, текущий шаг, нужную локацию и результат существующего валидатора. Практика не пропускает теорию; повтор или старый запрос не дублирует XP. После проверки показываются умения, балл, награда и конкретная следующая комната/сотрудник. «Продолжить» устанавливает следующую цель. Завершённая смена переводит в отдельное состояние courseFinished; промежуточного тупика complete нет. Старые студенты с завершённой первой главой получают главу 2 автоматически, без потери аккаунта и результатов.

Ольга Сергеевна в 220 работает с локальными/сетевыми файлами и финальными заявками. У Ольги и Дмитрия отдельные прозрачные PNG; промпты и метаданные в assets/npcs. Для новой версии перезапустите npm start, затем обновите страницу.

Определения протоколов сверены с первичными документами: [IPv4 – RFC 791](https://www.rfc-editor.org/rfc/rfc791), [ICMP – RFC 792](https://www.rfc-editor.org/rfc/rfc792), [DHCP – RFC 2131](https://www.rfc-editor.org/rfc/rfc2131), [DNS – RFC 1035](https://www.rfc-editor.org/rfc/rfc1035).


## Единая система инструкций

data/taskContracts.js содержит 249 контрактов этапов, практических действий и дополнительных упражнений/осмотра. ui/taskGuide.js использует текущий контракт для HUD, маршрута, механической помощи и маркеров. Практика разбита на отдельные действия; промежуточные схемы и действия сохраняются в существующем состоянии курса. Первый Network Lab показывает tutorial 1–4, повтор доступен через ?. В направляемых демонстрациях главы 2 студент подключает PC-01, главы 5 назначает первый IPv4, главы 7 собирает Router; сервер проверяет демонстрацию до перехода к тренировке. Поля имеют видимые объяснения и кнопку «Сохранить настройки».

Новая задача должна проходить register()/assertAll() и tests/task-contracts.cjs. Существующие темы не расширены. Подробный аудит, правило приёмки и границы E2E – TASK_UX_AUDIT.md.


## Стабилизация инструкций (04.10.2026)

Основная инструкция показана постоянно в блоке над стендом, который остаётся видимым при прокрутке. «Что делать?» раскрывает подробности без сброса схемы и формы. Один золотой маркер переходит между дверью, сотрудником, Ethernet, устройством, портом, адресным полем и проверкой. Декоративный знак не меняет доступные названия кнопок.

Task Contract требует 29 полей, включая mode, locationId, visibleInstruction, detailedInstruction, interactionType, expectedAction, wrongActionFeedback и questMarkerTarget. TRAINING направляет действия в демонстрациях и обучении подключениям главы 3; PRACTICE оставляет свободу и проверяет результат; FINAL/TROUBLESHOOTING сохраняет самостоятельное исследование заявок. Глава 3: три подключения, таблица портов, передача данных. /24 показывает отдельно сетевую и узловую части адреса.

Незаконченные направляемые демонстрации и практические черновики сохраняются в существующем состоянии SQLite; XP выдаётся только серверной проверкой. Проверка сети сообщает правильный результат, ошибку и следующий шаг. Учебные подсказки остаются отдельными тремя уровнями.

Полный запуск: npm test (в PowerShell при ограничении выполнения npm.ps1 используйте npm.cmd test). Тест авторизации запускает npm CLI через текущий Node без shell, использует отдельную БД, закрытый stdin и предел 30 секунд. Сквозной тест регистрирует нового студента и проходит 0–15 через клавиши движения, E и элементы интерфейса; tests/walk.cjs рассчитывает маршрут по коллизиям, но не меняет координаты или учебный прогресс.


## Стабилизация состояния заданий

Network Lab использует NETWORK_STATE_VERSION=2 и общий network/taskState.js для начальной схемы, миграции, предусловий и восстановления на клиенте/сервере. Контракт содержит taskInitialState, preconditions, postconditions и allowedActions. В TRAINING главы 3 разрешены только последовательные PC-01/02/03 → SW-01 Ports 1/2/3. PRACTICE допускает эксперименты с конкретными ошибками занятых портов и удалением лишнего кабеля.

Кнопка «Восстановить задание» возвращает текущую схему/черновик к началу, сохраняет XP и пройденные главы. F5 сохраняет промежуточный выбор кабеля. После Reset записи предыдущего поколения отклоняются. Canonical модель devices/links хранится в SQLite; UI отображает производные состояния портов.

Матрица всех существующих практик: NETWORK_TASK_MATRIX.md. Технические причины, изменения и фактическое покрытие: начало REPORT.md. npm test включает 22 серии; authentication и прежние проверки сохраняются. После обновления серверного кода перезапустите npm start и обновите страницу.

## Перед публикацией на GitHub

В репозиторий включаются исходный код, рабочие assets, tests, документация и package-lock.json. `.gitignore` исключает node_modules/, storage/, .prototype-checks/, .env и локальные варианты .env, логи, SQLite-базы и их журналы/WAL. Эти папки создаются локально при установке, запуске и проверках. `.env.example` можно включать только с пустыми значениями или примерами.

Исходные MP4 удалены: игра использует assets/idle.webp, assets/run.webp и assets/animations.json. Логи и снимки проверок, упомянутые в отчётах, генерируются локально и не публикуются. Development-аккаунт предназначен для локальных тестов; его параметры публичные, bootstrap отключён в production.
